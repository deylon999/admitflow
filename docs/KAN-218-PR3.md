# KAN-218, этап 3 — возобновляемый пакетный импорт

База — `main@89a98c5`. PR #30 объединил публичную часть пилота PR #28,
проверенную в [CI на 7ee9dbe](https://github.com/deylon999/admitflow/actions/runs/44920003451).
Целевая кампания — 2027, архив обрабатывается отдельной явной командой.

Пять шагов:

1. Аудит, выбор границ, подтверждение зависимости T317.
2. Реестр проверенных URL и кандидатов с разделением захвата и публикации.
3. Ограниченный пакетный CLI, checkpoint, повторы и диагностика.
4. Тесты частичного сбоя и повторной публикации на PostgreSQL, пробный запуск.
5. Отчёт с SHA и CI, передача на review.

Импорт одного документа из этапа 2 уже проверяет SHA, извлечённые факты,
год и идентичность, блокирует конфликт и переключает указатель атомарно.
Пакетный CLI переиспользует эту транзакцию и существующий HTTPS fetcher.
Единственный операторский каталог источников задаёт точные URL, а опубликованные
факты по-прежнему требуют проверенный пакет. Новые миграции не требуются.

До запуска согласованы границы проверки: запрещённый robots и отказ доступа
останавливают запросы, успешные исходники повторно не скачиваются при возобновлении,
временный сбой откладывает повтор, изменившийся SHA требует отдельной сверки,
а завершение пакета не означает полноту программ вуза. Сохранённые публикации
других вузов и кампаний должны пережить ошибку в любом одном источнике.

| Источник для проверки 2027 | Что подтверждает страница |
| --- | --- |
| [СФУ](https://sfu.ru/ru/admission/bachelor/exams-destinations?tab=e9253131d1a508) | Проект испытаний на 2027 год, таблица 2026/27, основная информация ожидается. |
| [РУДН](https://admission.rudn.ru/undergraduate/way/) | Университет ожидает публикацию правил 2027/28 до 20 января 2027 года. |

Эти страницы включаются только как кандидаты для сверки. Названия в анонсе,
проекты и прошлогодние таблицы не образуют проверенную запись кампании 2027.

## Запуск и восстановление

Из `backend/` с активным окружением проекта:

```text
python -m app.program_catalog_batch capture --year 2027 --work-dir var/research/kan218-pr3 --limit 3
```

`--source` можно передать несколько раз. Неизвестный ключ или ключ кампании
другого года отклоняется до сети. Перед загрузкой проверяется `robots.txt`
того же хоста. Операторский реестр фиксирует точный HTTPS URL. Дочерний
процесс ограничивает запрос 30 секундами включая DNS, таймаут транспорта
15 секунд. Переходы по redirect закрыты. Для robots допускается до 256 КиБ
`text/plain`, для документа — до 5 МиБ `text/html`. Правила запрета с `*` и
`$` проверяются консервативно. Временные файлы обмена и raw остаются закрытыми.

До десяти новых попыток на вызов, по умолчанию три. Один процесс удерживает
блокировку каталога захвата. Между запросами на хост выдерживается минимум
2 секунды или более строгая задержка из robots. `Crawl-delay` или `Request-rate`
с ожиданием больше минуты требует операторской проверки. Повтор после
ожидаемого временного сбоя откладывается до `notBefore` (UTC Unix timestamp),
с учётом `Retry-After` и возрастающей задержки. Не более трёх попыток на ключ
в рабочем каталоге. Ошибка доступа и запрет robots блокируют автоматический
повтор. Сохраняйте один рабочий каталог при возобновлении, включая ограничения
хостов. Новый каталог для свежего захвата имеет смысл после операторской
проверки причин отказа и окончания указанной задержки.

Checkpoint атомарно заменяется после каждой попытки. После прерывания
следующий запуск проверяет SHA уже сохранённых документов и продолжает
ожидающие источники. `pending`, `deferred` и `blocked` дают exit 1. Успешный
захват и `publication: eligible` означают доступность оригинала для повторной
валидации, а не запись в PostgreSQL.

Оператор публикует явной командой с уже обновлённым PostgreSQL, указанным
в `DATABASE_URL`, и отдельным закрытым `--raw-store`. Пример для проверенного
захвата в изолированной среде:

```text
python -m app.program_catalog_batch publish --year 2027 --source hse-design-2027 --captured var/research/kan218-pr3 --raw-store var/private-raw
```

`--reviewed-originals` вместо `--captured` использует архив этапа 2 с файлами
`<sha256>.html`. При работе с журналом новый SHA получает `review_required`;
ранний оригинал не подставляется вместо него. Указатель публикации и
источник проверяются в существующем импортере. После потери ответа достаточно
повторить ту же команду: зафиксированный набор вернёт `unchanged`, остальные
источники будут обработаны отдельно. Кандидаты, ошибки и розыск исходника
остаются видимыми в итоговом JSON. `allSourcesSucceeded` относится к выбранной
операции. `completeUniversityCatalog: false` сохраняется даже у зелёного пакета.

## Проверка на реальных оригиналах

21 ноября 2026 года захвачены три указанных выше оригинала и три robots.
Один дополнительный захват ИТМО проверил ограничение времени через отдельный
процесс. Повтор исходной пачки сделал **0 сетевых запросов**, сверив локальные
хеши. Три новых источника получили `review_required`, ни один не вошёл в API.
Выбранный пакет проверенных документов на PostgreSQL 17.11 дал ВШЭ 2027
`published → unchanged` с тем же ID ревизии и СГУ 2026 `published` в отдельном
запуске. На основном запуске `2027` с кандидатами exit 1 сохранил успешную
публикацию ВШЭ. API вернул две подтверждённые программы 2027 и четыре записи
за 2026, включая две прежние. `sgu-2026-4588` сохранил 16 мест.
[JSON с SHA, датами и результатами](evidence/kan-218-pr3-batch.json).

```text
backend/.venv/Scripts/python.exe scripts/verify_program_catalog_batch.py --output docs/evidence/kan-218-pr3-batch.json
backend/.venv/Scripts/python.exe scripts/test_postgres.py tests/test_program_catalog_batch.py
```

Локальная расширенная выборка прошла на PostgreSQL: 101 тест без пропусков
за 49,66 с. Финальные тесты самого пакета — 16 без пропусков за 3,34 с.
Проверены 13 тестовых источников через ограничение 10 попыток на вызов,
прерывание, отказ доступа, повреждённый кеш, конфликт хешей, повторы и разделение
лет. Синтетические сценарии не участвуют в подтверждённом каталоге.

Результат 2027 в изолированной БД — 1 из 785 головных вузов, две программы,
ноль новых подтверждённых конкурсов. Знаменатель датирован 10 ноября 2026 года.
Архив и более широкий национальный сбор оцениваются отдельно. Производительность
на национальном объёме входит в этап 4; выход на 60% — в следующие этапы.
