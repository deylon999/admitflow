# KAN-218 / T327 / KAN-223: согласованное расширение каталога

Владелец проекта явно согласовал направление 21 ноября 2026 года в текущем
задании: сохранить обратную совместимость, добавить `programId`,
`competitionGroups`, неизвестные условия как `null` и `provenance.kind=admissions`.
Основа — [реальный пример ВШЭ](response-proposal.json), сверенный с backend
`product_catalog_schemas.py` и frontend `catalog/types.ts`, `catalog/decode.ts`.

Все четыре endpoints, параметры поиска/пагинации, старые поля, их значения
и URL сохраняются. `id` остаётся публичной идентичностью записи в кампании.
Для новых записей он уже сохранён в `ProgramCatalogFact.public_id`; вычислять
его из названия или заменять при обновлении ревизии нельзя.

`programId` — отдельный ID существующего `Program`. Для прежних записей,
представляющих архивный конкурс, он **nullable**: заполняется только при
однозначной явной связи `CompetitionGroupProgram` с той же кампанией.
В имеющемся verified-наборе такой связи может не быть. Придумывать Program
или выбирать его по совпадению названия/кода нельзя. Это безопасное уточнение
аддитивного поля; прежние `sgu-2026-4588` / `sgu-2026-4576` остаются без изменений.

`competitionGroups` — массив подтверждённых конкурсов: `id`, `campaignId`,
`officialId`, `title`, `studyForm`, `funding`, `category`, `seats`, `provenance`.
Новые записи используют только group facts той же опубликованной ревизии
и явную M:N связь. Старые архивные записи сохраняют свой подтверждённый конкурс.
Неподтверждённый конкурс — пустой массив, не фиктивная группа. Места относятся
к указанной записи/конкурсу; суммы разных конкурсов не вычисляются.

`code`, `studyForm`, `funding`, `category`, `seats` допускают `null`.
Старые непустые значения сохраняют смысл. `historicalCutoff` и `forecast`
остаются null; требования ЕГЭ не переносятся на новые программы/кампании.
`sourceUpdatedAt` не подменяется датой проверки или датой документа.
Остальные capture/review/extractor metadata сохраняются в0014; публичный DTO
содержит только выбранные метаданные, без HTML, evidence JSON и raw paths.

Новый frontend принимает отсутствие аддитивных полей у старого сервера как
`programId: null` / `competitionGroups: []`, но отклоняет некорректные значения
и группы из другой кампании. Условия null показываются как «Нет данных».
Старый строгий decoder не понимает admissions/null: совместимость достигается
согласованным обновлением decoder и backend, без изменения дизайна/маршрутов.

Публичный read path читает только указатель `ProgramCatalogPublication` на
verified ревизию. Черновики, заменённые ревизии, отвергнутые попытки и
неоднозначные повторные публичные идентификаторы в выдачу не попадают.
HTTP endpoints ничего не импортируют и не публикуют автоматически.
