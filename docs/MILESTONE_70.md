# B12: функциональный рубеж оценки70%

Запрос2026-11-04: продолжать работу до ощутимого роста готовности MVP с прежней экспертной оценки60% до примерно70%. Это не измерение процента строк кода/карточек и не обещание готового публичного сервиса. Критерии зафиксированы до реализации;новая цифра сама по себе не закрывает работу.

Рубеж достигнут только после проверки всей цепочки:

1. Общий parser семейства работает на нескольких настоящих профилях через конфигурации;каждый scope аттестован отдельно. Никаких произвольныхURL или копии parser на каждую группу. Старые опубликованные версии не переписаны.
2. Два независимых официальных источника импортируются и сверены по реальным оригиналам (≥50строк или все,граница мест и спорные случаи). Реальные идентификаторы приватны;в Git обезличенные DOM с provenance. Архив остаётся архивом.
3. Версионированная автоматическая обработка даёт воспроизводимые факты/условные оценки для явно подтверждённых условий,а неизвестные поля/правила дают явный отказ. Не вычисляет официальный результат или вероятность из неполных данных.
4. Новый снимок сохраняет прежний результат,даёт проверяемый diff и объяснение. Детерминированный replay показывает изменение/отсутствие/ошибку/восстановление;синтетические изменения явно отмечены.
5. Изменения видны владельцу в интерфейсе,дедуплицированы и имеют идемпотентное прочтение. Есть рабочий полный локальный путь с настоящимAPI/PostgreSQL,двумя источниками,историей/сравнением и защитой двух владельцев.
6. Текущие значимые проверки проходят,локальная сборка доступна;TASKS/STATE/LOG и evidence обновлены.

Первые пять карточек:T187 механика scopes;T188 реальное повторное использование;T031 второй независимый источник;T034 assessments/diff;T039 объяснения. После них продолжить replay/изменения/UI до выполнения пунктов4–6. Не заменять этот рубеж дополнительными косметическими карточками.

После70% по-прежнему открыты:HTTPSstaging/production,remoteCI,суточное наблюдение,масштабная нагрузка/браузеры/пользовательская приёмка,национальный охват,source-use/productionretention/abuseполитики. Выпуск проверяется исходными gates,их критерии не снижены.
