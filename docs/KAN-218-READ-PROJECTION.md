Сравнение SQL, индексов и экспериментальных проекций выполняется до окончательной

## Обоснование хранения

Новая0015 добавляет производный индекс текущих immutable фактов и одну строку
политики. Это не новые программы/конкурсы и не замена source-backed таблиц.
Исходные facts, revisions, publication pointers, ID и исторические связи сохранены.
Проекция содержит ключи, условия поиска и сортировки; публичные факты/источники
по-прежнему гидратируются из оригинальной ревизии. Legacy СГУ проверяется отдельно
на каждом запросе, поэтому редактирование ручных/архивных строк не скрывается кешем.

## Атомарность и конфликты

Триггеры publication pointer действуют на INSERT/UPDATE/DELETE, включая прямой SQL.
BEFORE STATEMENT увеличивает epoch единственной строки политики: это сериализует
публикации и заставляет старый REPEATABLE READ writer получить serialization failure.
После изменения pointer удаляются старые read keys и добавляются новые. Для
затронутых public ID и program ID пересчитывается глобальная допустимость.
Сравнивается пара program/campaign; совпадение программы в другом году допустимо.
Все стороны конфликта исключаются. Неизвестная каталогу организация не влияет
на допустимость известных организаций. При снятии конфликтующей публикации
оставшаяся проверенная запись открывается в той же транзакции.

Частичные unique indexes защищают eligible public ID и program/campaign.
Прямые INSERT/UPDATE/DELETE derived rows запрещены; обслуживать их могут вложенные
триггеры публикации/политики. Ошибка любой проверки откатывает source pointer,
epoch и проекцию вместе. Квоты, места, факты другого года и M:N связи не выводятся
из поискового индекса и не меняют идентичность.

## Политика актуальности

TTL, фонового refresh и окна устаревания нет. Source pointer и read keys коммитятся
вместе. API читает fingerprint политики внутри того же REPEATABLE READ snapshot.
Fingerprint включает точный набор известных organization ID и reserved legacy ID.
Если он отличается от версии каталогов приложения, используется исходный точный
SQL. Это сохраняет поведение при разных версиях приложения и при обновлении
справочника: ответ может стать медленнее, но не использует устаревший eligible-набор.

`python -m app.catalog.read_projection refresh-policy` обновляет только derived
политику и её допустимость атомарно; hash проверяется в PostgreSQL. URL БД берётся
из обычных настроек и не печатается. Команда требует PostgreSQL; рабочая БД
в ходе разработки не используется. SQLite оставляет пустую policy и исходный SQL.

## Миграция

0015 использует замороженный список политики в `backend/alembic/data/0015_read_scope.json`.
Backfill выполняется из текущих pointers и immutable facts, с глобальной проверкой
конфликтов до включения быстрого чтения. Downgrade удаляет только derived объекты;
исходные кампании, факты и история остаются.0001–0014 не редактируются.
