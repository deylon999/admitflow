Рабочая ветка: `feat/kan-218-catalog-architecture`.

## 1. Проверенная исходная точка

Чистое дерево перед началом; `git fetch origin main` обновил main с
`591fa99` до `e121d5d`. Последние merged PR: #26 (названия вузов),
#25 (карточки вузов), #24 (авторизация UI). Их изменения сохранены.
Локальная ветка предыдущей работы не переписана. Настроенное авторство
`deylon999` сохранено. `roadmap --check`: 307 задач, структура корректна.

| `product_catalog.py` | Четыре действующих endpoints; сверка всей метаинформации с reviewed профилем; ручные правки не повышаются до verified | Program.id фактически равен CompetitionGroup.id; только два СГУ; `.all()` и Python-фильтрация/сортировка/пагинация; university counts снова читают программы |

Alembic: линейные revisions `0001`–`0012`; последняя — account foundation.
Применённые файлы не редактируются. Для будущего расширения нужна новая
аддитивная миграция и проверка на существующей схеме с данными в отдельном PG.
Текущее состояние рабочей БД аудитом исходников не устанавливалось.

React v3: `frontend/src/catalog/types.ts` и `decode.ts` строго проверяют
обязательные поля формы/финансирования/категории и provenance kind из трёх
значений. Новые значения kind, null вместо строк или список конкурсов требуют
предварительного согласования контракта с KAN-223. В этом PR публичные DTO,
frontend, авторизация и workflows не меняются.

Изучены тесты product_catalog, national_coverage, national_catalog, migrations,
migration_metadata, ci_migrations и native_support; pipeline contracts и
существенные проверки валидаторов/публикации. Существующие тесты покрывают
две СГУ, повтор, rollback, ручную порчу, архив и точный ЕГЭ. Массовый каталог
программ, отдельная идентичность Program и M:N ещё не проверяются.

Это аудит кода и сохранённых артефактов. Он не утверждает сегодняшнюю
доступность официальных сайтов, фактическое наполнение пользовательской БД
или достижение национального покрытия.
