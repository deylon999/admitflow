## Обязательная проверка

Профиль:100000 текущих программ плюс исторические ревизии. После прогрева
не менее50 измерений на каждый сценарий; отдельная нагрузка10/25/50 одновременных
запросов. p95: первая страница<200мс, вуз+год<150мс, код<300мс,
глубокая пагинация<500мс. Нужны память и нагрузка PostgreSQL, temp files,
buffers, планы, затраты публикации и миграции. Память Python отдельно.
Нельзя заменять точный total приближением или скрывать устаревание кеша.

Неизменяемые условия: глобальный карантин конфликтов, идентичность, история
кампаний, прежние DTO/API, явные M:N связи, атомарная публикация и согласованный
snapshot ответа. При невозможности достичь ориентиров требуются воспроизводимые
измерения, причины и оценка альтернатив. Самостоятельный merge запрещён.

## Варианты для сравнения

| Вариант | Работа при чтении | Обновление | Основной риск |
| --- | --- | --- | --- |
| Текущий SQL/anti joins/CTE | Глобальные проверки, точный count, sort/OFFSET | Только исходная публикация | Повторное чтение всего текущего набора, spill и плохая оценка cardinality |
| SQL и индексы | Проверки в запросе; индексированные фильтры/поиск/порядок | Дополнительные индексы на исходных facts | История увеличивает индекс; глобальная проверка может оставаться дорогой |
| Транзакционная проекция текущих подтверждённых фактов | Чтение готового eligible-набора, точный count и индексы | В той же транзакции, что смена публикации; старые/новые ключи проверяются глобально | Сериализация конфликтующих публикаций, backfill, полнота всех путей записи |
| Materialized view с refresh | Готовая проекция | Полный refresh и переключение версии | Нельзя допустить промежуток устаревания или refresh вне исходной транзакции |
| Кеш ответов | Готовые страницы/count | Инвалидация на каждый commit | Без строго определённой версии/snapshot не подходит |

Проекция рассматривается как ускорение существующего каталога, а не новый
источник фактов или новая идентичность. Если выбрана, исходные immutable facts
и publication pointers остаются источником истины. Новая миграция должна
backfill существующие публикации, поддерживать rollback и все прямые SQL-пути
обновления pointers, а не только операторский Python CLI.
