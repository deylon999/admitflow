# Визуальная система AdmitFlow

Синий акцент, нейтральные поверхности, обычный CSS и существующий Inter
сохранены. Система применяется внутри текущей архитектуры; новые страницы,
бизнес-сценарии, UI-библиотеки и дополнительные пользовательские шаги не добавлены.

## Типографика

| Роль | Размер | Межстрочный интервал |
| --- | --- | --- |
| h1 | 32px, на экранах до600px —28px | 1.25 |
| h2 | 24px | 1.25 |
| h3/h4 | 20px | 1.25 |
| Основной текст, значения полей | 16px | 1.5 |
| Второстепенный текст, labels, кнопки | 14px | 1.5 |
| Подписи и badges | 12px | 1.5 |

Большие значения48/64px используются только для числового результата и
метрик, не заголовков. Font weights:400/500/600/700; заголовки600.
Значения определены в `frontend/src/app/styles/tokens.css`.

## Отступы и поверхности

Базовый шаг4px; типовые интервалы8/12/16/20/24/32px. Между крупными
секциями64px на широком экране и48px на узком. Padding карточек24px/20px.
Радиусы:4px для небольших меток,8px для управления,12px для карточек.
Границы1px. Светлая тема — мягкий фон и белые поверхности, тёмная —
согласованные тёмно-синие поверхности. Цвета текста, линий, ошибки,
предупреждения, hover и focus задаются семантическими токенами.

## UI-компоненты

Публичные экспорты находятся в `frontend/src/shared/ui/index.ts`:

- `Button`: primary/secondary/ghost/danger/option, нативные props и ref.
  Размер управления минимум44×44px, текст14px. Default variant —secondary.
  Native type сохраняется: назначайте `type="button"` или `type="submit"`
  явно при использовании внутри форм.
- `Input` и `Select`: высота44px, текст16px, общие границы/focus/invalid/
  disabled. Checkbox/radio сохраняют нативное поведение. File input имеет
  оформленный нативный file selector.
- `Card`: общий фон, border, radius и padding. `as` сохраняет семантику
  article/section/aside/details/form; дополнительной DOM-обёртки нет.
- `Badge`: единая компактная метка12px.
- `Alert`: error/info/warning; `as` сохраняет p/div. ARIA role передаётся
  вызывающим кодом, стили не создают новых автоматических объявлений.

Ссылки с поведением React Router остаются ссылками и используют тот же
CSS-рецепт `button button-primary` либо `button button-secondary`.
Модификаторы `button-compact` и `button-icon` сохраняют44px высоты и
применяются в шапке. Компактная кнопка не разрывает короткое слово по буквам.

Фокус управления — явное кольцо3px. Программный фокус на заголовках/main
сохраняется без декоративной рамки. Disabled не получает hover-окраску.
При reduced motion переходы отключаются. Цвет meta theme-color читается
из того же токена фона. При печати действует отдельный слой оформления.

## Порядок CSS

`tokens → base → layout → components → print`.

App подключает токены и базу, затем существующую раскладку и общий
`shared/ui/ui.css`. Из старых файлов убраны дублирующиеся правила базовых
элементов и управления. Контекст страницы не должен переопределять
типографическую шкалу или оформление кнопок/полей. Layout отвечает за
сетку, размещение и содержательные интервалы. Print сохраняет отдельные
размеры отчёта; палитра экрана не переносится на бумагу.

Проверка: `node scripts/check-design-system.mjs` из frontend с доступным
compiled preview5285 (E2E_BASE_URL можно изменить). Используются только
синтетические route mocks, сервер API не требуется. Скрипт проверяет
12 сочетаний страница/тема/ширина и4 состояния редактора, включая hover
контраст основной кнопки≥4.5. Это ограниченная проверка выбранных состояний,
не утверждение о полном accessibility-аудите всего приложения.

Аудит, результаты и полный перечень файлов: [отчёт](evidence/design-system.md).
