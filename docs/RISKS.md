## Реестр открытых решений

| Вопрос | Текущая рабочая позиция | Когда нужен ответ |
| --- | --- | --- |
| Какие вузы для технического пилота? | Пользователь хочет все; исполнитель выбирает кандидатов по доступности/форматам и документирует выбор | T009 / G1 |
| Какой сезон и уровень приёма? | Бакалавриат/специалитет как стартовый технический поднабор; сезон ещё не утверждён | T010 до автоматического расчёта |
| Нужны ли аккаунты уже в MVP? | Гостевой режим начат; ограничение должно быть видно пользователю | Приёмка G2 |
| Где размещать, какой бюджет? | Один Linux-host и Docker Compose предложены; платный ресурс не заказан | До T048 |
| Кто оператор данных и каковы сроки хранения? | Не определено; техническая минимизация не заменяет решение | До публичного запуска |
| Есть ли исторические данные для вероятности? | Не предоставлены и не проверены | T060; не блокирует сценарный MVP |
| Требуется ли отдельный дизайн кабинета? | Использовать существующие tokens и типографику; кабинет отсутствует в исходных PNG | Приёмка G4 |

## Правило управления риском

Проверенная проблема переносится в задачу с доказательством. Гипотеза остаётся помеченной как гипотеза. Для внешнего блока указывать последнее наблюдение и условие снятия; не бесконечно повторять одну и ту же неуспешную команду без нового основания.

После изменения объёма обновить PRODUCT, ADR, зависимости задач и gates. Не прятать сокращение объёма за переименованием релиза.
