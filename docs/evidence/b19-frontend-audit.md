# B19: глубокий аудит frontend — 10 подтверждённых дефектов

Проверено 06.11.2026. Поведение соответствует5440410: текущие изменения —
только читаемое форматирование, настройки formatter и документация.
Функциональные дефекты ниже **не исправлены** по исходному указанию пользователя.

Проверки выполнялись в Chromium/Firefox, на compiled preview5281 с отдельным
SQLite API8031. Для гонок/ошибок использовались задержки отдельных запросов и
синтетические route mocks. Реальные абитуриенты, приватный ключ и прежняя база
не использовались. Два критичных сценария дополнительно повторены основным
исполнителем после форматирования. Исходные probes сохранены локально в
ignored backend/.pytest_cache/audit_*; воспроизведение и причины ниже.

| --- | --- | --- |
| F01 | P1 | Ранняя синхронизация вкладки приводит к удалению новой сессии и записи |

## F01. Восстановление доступа из второй вкладки удаляет новую сессию

Места: [api.ts](../../frontend/src/lib/api.ts), resumeSession204,
resetSession217–229; [TrackerPage.tsx](../../frontend/src/pages/TrackerPage.tsx),
synchronize444 и recovery CTA656; [query-client.ts](../../frontend/src/lib/query-client.ts),27.

1. Открыть один гостевой кабинет в двух вкладках A/B.
2. В B подтвердить «Удалить всё», задержать её новый POST/session после DELETE.
3. A уже показывает «Гостевой доступ изменён». Нажать «Синхронизировать доступ».
4. GET/session попадает в промежуток без cookie, получает401; A предлагает
   «Начать новую сессию» вместо ожидания синхронизации.
5. Разрешить POST в B и сохранить запись в новой сессии.
6. Нажать предложенную recovery кнопку в A. Новая сессия B удаляется.

Проверено настоящим synthetic API: **число новых записей1→0**. Resume не
использует тот же guest lock, а storage event публикуется между удалением и
созданием сессии. Промежуточный401 преобразуется в expired; recovery выполняет
destructive reset. Probe:audit_sessions_race.cjs. Cleanup выполнен.

## F02. «Удалить всё» оставляет старые карточки после успешной смены сессии

Место: [TrackerPage.tsx](../../frontend/src/pages/TrackerPage.tsx), reset.onSuccess494,
особенно invalidateQueries510.

Создать запись, подтвердить сброс и вернуть503 только на обновление GET/watches
новой сессии. Интерфейс сообщает «Создана новая гостевая сессия», но показывает
карточку прежнего владельца. Настоящий API новой сессии возвращает0записей,
React UI продолжает показывать1. Старый watches.data также используется
печатным ManualReport. Другие private query keys очищаются, watches только
инвалидируется; неуспешный refetch оставляет прежнюю копию данных.

Это сохранение старой private копии во frontend после сброса, не доступ к
чужим серверным данным. [Скриншот](b19-stale-session.png).
Probe:audit_sessions_stale_reset.cjs, основной исполнитель повторил результат.

## F03. Черновик возвращает отменённые значения

Место: [DirectionForm.tsx](../../frontend/src/components/DirectionForm.tsx),
dirty60 и persist effect86.

В сохранённой записи с номером10 открыть редактирование, ввести11, затем
вернуть10. Перезагрузить кабинет и восстановить черновик: появляется11.
Аналогично новая форма восстанавливает название вуза, которое пользователь
целиком стёр. При dirty=false persist effect не обновляет и не очищает
предыдущую запись sessionStorage; предупреждения о несохранённых изменениях
при этом уже нет. [Скриншот](b19-draft-restores-cancelled.png).
Probe:audit_forms_probe.cjs, настоящая synthetic API запись.

## F04. Перечитывание фактов оставляет историю старой

Места: [ArchiveDirections.tsx](../../frontend/src/components/ArchiveDirections.tsx),91;
[ArchiveHistory.tsx](../../frontend/src/components/ArchiveHistory.tsx),64.

Раскрыть историю snapshot-1. Переключить синтетический сервер на snapshot-2,
продвинуть browser clock на31секунду и нажать «Перечитать сохранённые факты».
Карточка/provenance уже показывают snapshot-2 от02.11, история — snapshot-1
от01.11. Запрос history остаётся единственным. Ключ истории содержит только
subscription ID; records.refetch не инвалидирует историю. Истечение staleTime
само запрос не запускает. Probe:audit_sources_probe.cjs.

## F05. Сетевая ошибка выдаётся также за отсутствие групп

Место: [SourcesPage.tsx](../../frontend/src/pages/SourcesPage.tsx),110.

При HTTP503 для GET/groups одновременно видны «Не удалось загрузить группы»
и «Подходящих подключённых групп пока нет». Отсутствие данных не установлено:
каталог просто не получен. Empty guard исключает pending, но не isError.
[Скриншот](b19-catalog-error.png). Probe:audit_sources_probe.cjs.

## F06. Каталог ломается при101подключённом филиале

Места: [source-contracts.ts](../../frontend/src/lib/source-contracts.ts),211;
backend контракт: [source_catalog.py](../../backend/app/source_catalog.py),89.

Валидный HTTP200 с50items/total100/100branch facets показывает50карточек.
Тот же контракт с50items/total101/101branch facets отвергается parser и
показывает ошибку вместо карточек. Пагинация задана корректно. Backend
возвращает глобальные facets без такого ограничения до применения фильтров;
выбор одного вуза проблему не обходит. Это не нагруженный benchmark и не
нынешний outage: соответствие границы frontend/backend проверено на mocks.
Probe:audit_sources_probe.cjs, отдельный branches101 case.

## F07. Сравнение не сообщает об изменившемся количестве мест

Место: [ArchiveHistory.tsx](../../frontend/src/components/ArchiveHistory.tsx),
Difference23.

Сравнить старый снимок seats2/candidate present и новый seats5/candidate absent.
Видно только сообщение об отсутствии записи; изменение мест2→5 не выводится.
Ранний return при null candidate выполняется до проверки group.seats.
Количество мест относится к группе и не зависит от наличия конкретной записи.
Probe:audit_sources_probe.cjs, capacity case, синтетические снимки.

## F08. После отмены неудачного импорта остаётся ложное предложение повтора

Место: [ImportData.tsx](../../frontend/src/components/ImportData.tsx),clear45,
cancel178 и mutation error185.

Выбрать корректный JSON, получить503 при импорте и нажать «Отменить импорт».
input.files=0, preview и кнопка импорта исчезают, но остаётся красное сообщение
«Повтор использует тот же ключ операции». Повторить уже нечего. clear не
сбрасывает mutation state, а error выводится независимо от prepared.
Probe:audit_forms_import_cancel.cjs; только синтетический mock503.

## F09. Ctrl+P печатает время открытия кабинета вместо текущего

Место: [TrackerPage.tsx](../../frontend/src/pages/TrackerPage.tsx),reportDate291,
собственная кнопка печати915.

Открыть кабинет в10:48, продвинуть browser clock до10:58, вызвать штатную
печать браузера. В отчёте остаётся «сформирован:10:48». reportDate задан при
mount и обновляется только собственной кнопкой; beforeprint не обрабатывается.
Собственная кнопка проверена отдельно и обновляет время правильно.
Probe:audit_forms_print.cjs; synthetic record/browser clock.

## F10. Две секции теряют CSS границы

Место: [tracker.css](../../frontend/src/tracker.css),790 и902.

.source-lookup border-top и .scenario-comparison border используют --border,
которой в стилях нет; объявлена --line. На реальных rendered elements
подтверждены borderStyle:none и borderWidth:0px при пустой --border.
Probe:audit_sources_probe.cjs. CSS при форматировании не менялась семантически.

## Дополнительное наблюдение и пределы аудита

Session DTO с expiresAt через1.8секунды: через2.4секунды кнопка добавления
остаётся активной; session-info staleTime=Infinity, таймера нет. Это наблюдение
о своевременности UI, а не обход серверного срока; отдельное решение о
проверке/отображении истечения требуется до классификации исправления.

Не подтвердились гипотезы горизонтального overflow на проверенных ширинах
320–1920 для landing/catalog и постоянно видимой skip-link: её обычный rect
находится наy=-160. Случайный full-page capture не считается доказательством
пользовательского дефекта. Гонка собственной кнопки печати также не подтверждена.

Регрессия после форматирования:116Vitest/build,79compiled Chromium passed,
36scopedskips. Ни один из этих прогонов не содержит все перечисленные новые
условия. Поэтому зелёный CI не является доказательством отсутствия ошибок.
Метрики читаемости/эквивалентности: [b19-format-verification.json](b19-format-verification.json).
