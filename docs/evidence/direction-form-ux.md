# T234 — понятная форма направления

Acceptance до реализации (2026-11-07, S191): одна форма без лишних шагов;
понятная последовательность и группы полей, человеческие названия, примеры и
связанные с полями подсказки/ошибки. Все сохраняемые поля остаются обязательными;
выбор вуза из справочника необязателен. Не предлагать 0 вместо неизвестного
числа; объяснить один конкурс и непересекающиеся группы. Редактирование обновляет
только числа и сохраняет историю. Ввод не теряется при отказе/повторе; ожидание,
ошибка и успех понятны. Мобильная/клавиатурная проверка, typecheck/lint/build и
релевантные тесты. Формулы, validation predicates, API, идемпотентность, guards,
правила черновиков/сохранения и backend неизменны. Без коммитов.

## Результат

Все пять шагов выполнены. Изучены DirectionForm, CalculationInputs,
UniversityPicker, DraftRecovery, direction validation, useDirectionForm,
useDirectionWorkspace, useUnsavedDirectionGuard, draft-store, calculator,
manual API и DATA_RULES. Прежние локальные изменения T233 сохранены; проверки
относятся к совокупной актуальной рабочей сборке, а не старому dist/HEAD.

- Одна форма, три fieldset/legend: «Вуз и направление», «Данные из конкурсного
  списка», «Кто находится выше вас». Семь обязательных полей сохранены.
- Поле «Направление» поясняет форму обучения и конкурс. Ссылка имеет пример
  и указание, что цифры по ней не загружаются автоматически. Выбор вуза из
  подсказок необязателен; ручной ввод работает и при отказе справочника.
- Короткие подписи двух сложных чисел опираются на заголовок о людях выше
  пользователя и постоянные подсказки. Контекстная справка объясняет два
  непересекающихся подсчёта, пример120/90/30/16 и ограничения результата.
  Неизвестное значение не предлагается заменять нулём. Это пояснение
  существующих DATA_RULES; формулы и правила не менялись.
- Numeric errors расположены у первого затронутого поля; при ошибке двух
  групп оба поля помечены invalid и связаны с одной ошибкой. Подсказки
  связаны с полями; остальные поля не ссылаются на чужую ошибку. Фокус
  остаётся управляемым прежней валидацией. Дублирующий нижний error убран.
- Редактирование показывает readonly вуз/направление и ссылку в новой
  вкладке. Обновляются только четыре числа; прежние снимки остаются в истории.
- Ожидание блокирует изменение/повтор/закрытие; форма обозначена aria-busy.
  При 5xx/обрыве/409 сообщение не утверждает, что запись точно не произошла.
  Ввод остаётся в форме; обычная кнопка повторяет прежний безопасный save.
- Под кнопкой объяснён результат сохранения. Успех использует существующие
  notice, закрытие формы и возврат фокуса. Есть нижняя отмена с прежним
  подтверждением потери ввода. Черновик явно отделён от сохранённого направления;
  текст восстановления не раскрывает внутренние ключи операций.
- Использованы текущие Card/Button/Input/Alert, design tokens и нативные
  details/summary. Остальные сценарии CalculationInputs на калькуляторе
  сохраняют подписи и поля. Удалены три неиспользуемых CSS-правила старой формы.

Не изменены: frontend/features/edit-manual-direction/model, calculator/model,
manual-direction/api, shared fixtures, DATA_RULES и backend. Проверка Git diff
по этим путям не обнаружила изменений. Формат save, idempotency key, expected
snapshot, default0, integer bounds, readonly metadata и TTL черновика прежние.
