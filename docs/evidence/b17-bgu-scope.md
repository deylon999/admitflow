# B17/T205 — точный GET scope БГУ

2026-11-05 UTC, свежий pinned HTTPS/robots=allowed. Официальный источник:
[БГУ, bachelor rating](https://bgu.ru/abitur/bach/rating.aspx).
Public configuration: `docs/sources/bgu2026-scope.json`; original bytes private
в ignored `backend/var/research/b17-bgu/`, SHA зафиксирован в конфигурации.

Проверены выбранные значения и подписи всех пяти select: бакалавриат,
с оплатой обучения, очная форма, основной приём, 08.03.01 Строительство /
«Организация строительного производства» (program14629). Объявленный план20
совпадает с ёмкостью в выбранном публичном option. Объявлено109заявлений,
в таблице109строк; номера полного порядка в двух колонках совпадают с1..109.
Checkbox сокращённого просмотра не установлен; pagination не обнаружена.
Это один точный default GET scope, не все21направление и не поддержка POST.

Таблица содержит дополнительные CSS колонки порядка, отсутствующие в логической
шапке: их нельзя принимать за код, приоритет или согласие. Проверены17TD и роли
каждой колонки. Сумма конкурсных баллов — колонка6, полный порядок — колонка4,
кодовый блок — колонка3. Дополнительный номер платного рейтинга не становится
приоритетом. Оплата договора не становится согласием.

Составной код имеет три части. Для lookup используются только первые5цифр:
все109значений уникальны в этом scope. Остальные части, включая персональный
идентификатор, не нормализуются/не запрашиваются у пользователя. Дубли первого
сегмента при повторном импорте должны отклоняться. HMAC остаётся ограниченным
source/group/year; нельзя сопоставлять людей между вузами по этому номеру.

14строк имеют явный текст «Зачислен» с приказом в отдельном span; прочие
participation=unknown. Consent и priority неизвестны у всех строк. Дата данных
без явной timezone не превращается в UTC: sourceUpdatedAt=null. Архив2026
не fresh и не даёт бюджетный числовой сценарий.

Проверка подготовительной конфигурации прошла на новом оригинале и совпала
по scope/count с сохранённым B16 оригиналом; количество/минимальные коды/
формат/порядок проверены без их вывода. Конфигурация пока attested=false;
до независимой сверки и закрытого manifest источника в БД не создаётся.
В подготовительной диагностике широкий ancestor span однажды захватил строки
в выводе; исправлен leaf/no-table фильтр. Tracked отчёты и fixtures не содержат
реальных строк/кодов. Дальнейшие проверки выводят только whitelist metadata.
