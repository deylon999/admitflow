# B17: новый архив БГУ и сохранность локального стенда

Пятёрка T205–T209 добавляет один точный архивный конкурс пятого вуза.
Официальный GET БГУ: бакалавриат2026, очное платное08.03.01 «Организация
строительного производства»,20мест/109строк. Все строки независимо сверены
по порядку, минимальной идентичности, сумме баллов, неизвестным согласиям/
приоритетам и явному статусу зачисления. Другие настройки формы и POST
не подключены; государственный бюджетный сценарий этой группе не назначен.

Новая версия общего decoder `reviewed-filtered-table-v1` проверяет выбранные
контролы, шапку/роли ячеек, программу, места и объявленное число строк.
Для scoped HMAC/поиска используется только первый пятизначный сегмент кода.
Персональные части не нормализуются и не запрашиваются в интерфейсе.
Новые кандидатные fixtures полностью синтетические; прежние14профилей/
proofs сохранены. Паспорт: [bgu2026.md](../sources/bgu2026.md).

## Фактический импорт

- [Native runtime](b17-bgu-runtime.json): настоящая HTTPS загрузка через
  bounded worker, PostgreSQL, независимая сверка всех109 текущих строк и
  stored audit. Исходный proof сохраняет прежний hash; другая загрузка
  не выдаётся за побайтово тот же оригинал.
- [Импорт в существующий demo](b17-demo-import.json): ещё одна настоящая
  HTTPS загрузка, независимый аудит перед публикацией,20мест/109строк.
  Все15сохранённых снимков прошли offline audit. Hash/count прежних14снимков
  и1775строк совпали до/после; исходные факты не переписаны.
- [Рабочий стенд](b17-local-demo.json): http://127.0.0.1:8091/sources,
  те же Compose project/key/volumes, схема0011, четыре сервиса. Worker
  ежедневно перепроверяет15архивов. Private pg_dump перед импортом сохранён
  в ignored `backend/var/b17-before-bgu.dump`; ключ не регенерировался.
- Покрытие:1257записей опорного каталога,15импортированных архивных групп
  пяти вузов,1884строки,2условных бюджетных сценария,0fresh.
  `nationalTotal=null`; T056/T057 остаются открытыми.

## Пользовательский путь и регрессия

На отдельном синтетическом API проверены lookup по минимальному коду,
подтверждение/повтор сохранения, изоляция владельцев, отсутствие кода в
экспорте/ошибках/localStorage/sessionStorage и очистка input после сохранения.
В настоящем demo браузер проверяет публичную карточку/инструкцию с пустым
полем; реальные идентификаторы абитуриентов не вводились.

Полная backend регрессия в Linux с обязательным native PostgreSQL:
**666passed/0skipped,428.96s**. **116Vitest и production build** прошли
повторно после финального исправления интерфейса.

Первый полный compiled Chromium run дал83passed/31scopedskips/1failure:
список вузов иногда закрывался при блокировке нажатой кнопки следующей
страницы. Перед fetch фокус теперь возвращается в поле поиска. Проверка
удерживает реальный ответ offset50 и проверяет открытый список и фокус,
затем разрешает загрузку. Финальные результаты и режимы запуска указаны
в [b17-final-verification.json](b17-final-verification.json); пропущенные
fixture/edge cases не учитываются как passed.

Фактические JS/CSS, включая lazy chunks, сравниваются с локальным dist.
Публичные desktop/320px screenshots просмотрены, горизонтального overflow
нет: [desktop](b17-bgu-group.png), [320px](b17-bgu-group-mobile.png).
Составные идентификаторы и отброшенные персональные части не найдены в
изменённых/новых B17 артефактах и текущем dist:
[ограниченная проверка](b17-privacy-scan.json). Во время первоначальной
диагностики T205 ancestor span попал в один tool output; исправление
leaf/no-table и ограничение последующих выводов агрегатами записаны в LOG.

Полный национальный охват, живая кампания,24часа наблюдения, HTTPS staging,
публичный production и свежая Firefox/WebKit проверка этим подходом не закрыты.
Следующий шаг: другой официальный GET scope из инвентаризации, независимый
аудит и подключение через общее семейство. Другие фильтры БГУ требуют
отдельного подтверждения транспорта, полноты и выбранного конкурса.
