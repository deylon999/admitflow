# T233 — состояния запросов frontend

Acceptance до реализации (2026-11-07, S190): loading, подтверждённый пустой
результат и ошибка различаются; общий Empty State tracker допустим только
после успешного чтения ручных и архивных направлений; одна критическая ошибка
с повтором, компактные локальные ошибки дополнительных разделов без дублей;
кэшированные данные и черновик сохраняются при фоновом отказе; важные действия
имеют понятное подтверждение. Используются существующие React Query/error
механизмы, без изменений backend/API/формул/архитектуры и без коммитов.

## Реализация

Все пять шагов выполнены. Изменения ограничены представлением состояний,
небольшими вспомогательными функциями и соответствующими тестами.

1. В tracker основной model наблюдает существующий query архива с тем же
   ключом и общим кэшем. Общая пустота требует двух успешных пустых списков;
   пока архив ожидается, пустой ручной список не объявляет пустым весь кабинет.
2. Первичный отказ получает один Alert с повтором. Ошибка архива при доступных
   ручных карточках локальна; при общем отказе она не дублирует основную ошибку.
   Фоновая ошибка сохраняет карточки/черновик/сравнение; прошлый пустой список
   описывается как прошлый результат, без утверждения о текущей пустоте.
3. RequestFeedback использует существующие Button и токены для компактных
   локальных сообщений с role=status и повтором. Открытые история/лента,
   архив, сведения об источниках и справочник вузов имеют локальное состояние.
   Лента и сведения об источниках впервые запрашиваются при раскрытии.
4. Кэш сведений об источниках и изменения позиции сохраняются при фоновом
   ожидании/отказе. Ошибка истории в карточке не повторяется, когда открыта
   полная история. Ошибка следующей страницы каталога оставляет предыдущие
   группы и предлагает один повтор именно следующей страницы.
5. Успех сохранения/удаления/обновления/подготовки файла виден в aria-live
   уведомлении; успех обновления не показывается при отказе части запросов.
   Подготовка файла не утверждает завершение скачивания. Проверка лимита,
   необходимая для добавления/импорта, при отказе получает объяснение и повтор.

Обработка запросов остаётся прежней: React Query, retry/cancellation/session
guards и текущие parsers. ApiError перемещён внутри shared/api для использования
существующего HTTP status при выборе текста. Для 5xx не показываются внутренние
detail; сеть/таймаут/некорректные данные остаются ошибками. Валидация форм и
контракты backend не менялись. Не добавлены фиктивные ответы или новые расчёты.
