# T237 — регрессии E2E после изменений UI

Acceptance записан в TASKS.json до реализации (S195, 2026-11-07): воспроизвести
ошибки из пользовательского лога Firefox, различить неполные fixtures,
устаревшие ожидания UI и ошибки приложения; сохранить проверки приватности,
не скрывать сбои увеличением таймаутов или новыми skip. Проверить затронутые
сценарии с изолированным API и записать фактические результаты.

## Причины и исправления

1. В tracker-tools синтетические watches/session были подменены, а автоматически
   загружаемая история PositionChange — нет. В Firefox воспроизведён в точности
   таймаут «Обновить цифры» с detached DOM. Network trace: session POST 204,
   session GET 200, watches GET 200, **watch-1/history GET 401** из настоящего API.
   Приложение правильно скрывало приватные карточки. Добавлен исходный ответ
   истории в beforeEach; отдельные тесты истории по-прежнему задают свои ответы.
   До исправления без живого API этот промах маскировался сетевой ошибкой вместо
   401. Проверка с настоящим изолированным API теперь обязательна для этой сверки.
2. В keyboard учтены два доступных по Tab summary с пояснениями. Перед движением
   дальше тест ждёт завершения поиска университетов, чтобы дебаунс и варианты
   справочника не меняли ожидаемую последовательность фокуса.
3. В draft-recovery возврат фокуса проверяется на кнопке в заголовке tracker:
   в пустом состоянии есть ещё одна одноимённая кнопка. Общее ожидание падало
   из-за strict mode, хотя фокус возвращался на правильный элемент.
4. В session-actions история уже находится в свежем 30-секундном кэше, поэтому
   открытие не обязано отправлять запрос после удаления cookies. Тест переводит
   часы за окно свежести и явно ждёт **реальный history 401**. Затем по-прежнему
   проверяет закрытие формы/карточек и отсутствие автоматического старта сессии.
   Физического ожидания, увеличения таймаута или изменения кэширования приложения нет.
5. В session-reset-cache инструменты могут оставаться disabled внутри закрытого
   details либо отсутствовать во время reset. Проверяется отсутствие активных
   export/print controls, включая скрытые, а также карточек, истории, фильтров
   и старого текста в DOM. Проверки задержанного ответа предыдущего владельца,
   нового авторизованного чтения и реального состояния API сохранены. Ожидания
   технических Synthetic ... сообщений заменены пользовательскими формулировками.

Изменены только пять E2E-файлов и документы. Код приложения, backend, API,
таймауты, число retries и условия skip не менялись. Ошибки не маскируются.

## Проверки

Изолированный FastAPI/SQLite создан во временном каталоге вне репозитория;
существующая база не использовалась. Frontend — актуальная production-сборка,
Vite preview 127.0.0.1:5285, E2E_API=1. Браузеры настоящие Playwright Chromium
и Firefox. Firefox внутри sandbox падает при newPage; вне sandbox работает.

- Затронутые пять файлов: **39 Chromium passed**, **39 Firefox passed**,
  без пропусков и повторов тестов. Все 14 упомянутых в логе сценариев входят
  в эти прогоны.
- typecheck, lint, build, format:check, architecture:check — exit 0.
- Vitest — **150 passed / 25 файлов**.
- Полный broad Firefox: **254 passed, 37 skipped, 0 failed (3.8 min)**,
  всего 291 тест. Без retries. Все 14 сценариев из пользовательского лога прошли.
  Существующие 37 skips требуют source fixtures/специального API или reverse proxy;
  условия пропуска не менялись.
- После уточнения проверки прежнего счётчика направлений дополнительно прошли
  все 4 session-reset-cache теста в Chromium и все 4 в Firefox.
- git diff --check и roadmap --render --check прошли.

При полном прогоне прошла и матрица final-ui-quality во всех четырёх размерах
и обеих темах. Просмотрены реальные Firefox PNG: [форма на 375 px](ui-ci-firefox-form-375.png)
и [tracker на 1920 px](ui-ci-firefox-tracker-1920.png). Историческое ограничение
T236 на запуск Firefox снято для этого локального прогона вне sandbox.

Это локальная проверка на Windows с изолированным API; результат нового
GitHub Actions run на Ubuntu пока не получен. Архивные source-fixture suites,
production reverse proxy, физические устройства и deployment отдельно не проверялись.
Временные preview/API остановлены, созданная только для проверки SQLite удалена.
Исправления сохраняются локальным коммитом по действующему запросу пользователя;
push не выполняется.
