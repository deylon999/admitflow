# B16/T202 — атомарная регистрация профилей

2026-11-05. Операторская команда `python -m app.sources.batch ID [ID ...]`
принимает1–100различных точных ID из закрытого manifest. URL, неизвестные ID,
дубли и превышение лимита отклоняются до подключения к БД. По умолчанию новые
источники disabled; существующие enabled источники не выключаются.
`--enable` использует прежний стабильный ключ/runtime registry; команда не
генерирует ключ, не запускает fetch/очередь и не включает числовые сценарии.

Все University/Campaign/Group/Source и журналы набора фиксируются одной
транзакцией. Ошибка позднего профиля откатывает предыдущие изменения набора.
Существующие метаданные и parser versions проверяются, не перезаписываются.
Карантин не снимается. Source блокируется до проверки enable/quarantine.
Общий catalog mutex используется single/batch/pilot/seed, поэтому параллельные
профили одного вуза не соревнуются за создание University/Campaign.

`--plan` выводит только публичные scope metadata без обращения к БД/ключу;
databaseChecked=false явно означает, что конфликты в БД ещё не проверялись.

Проверки:41native targeted passed/0skip(10.69s), включая старый source API,
карантин и секции. Затем расширенный batch suite14passed/0skip(3.35s): весь
реальный manifest14профилей, повтор, полный откат, пустой registry/ключ,
поздний карантин,8конкурентных пересекающихся наборов+single, сохранение
legacy parser и максимальный набор100синтетических disabled профилей.
Синтетический набор не создаёт snapshot/job и не добавляет реальное покрытие.
Паспортов новых реальных источников этим шагом не добавлено.
