# Итоговая архитектура frontend

Исходное состояние, решение для каждого из 46 файлов и границы CSS
зафиксированы до переноса в [аудите](frontend-architecture-audit.md).
Изменения разделены на демонстрационные страницы и связанную поверх них
ветку с маршрутизацией, аккаунтом и реальными функциями. Статус двух частей
ведётся в T335.

## Карта после реорганизации

| --- | --- | --- |

Маршрутизатор импортирует публичные входы экрана. Соседние feature-области
переиспользуют навигацию и общие UI/ресурсные примитивы. Фильтры конкурсов
больше не проходят через каталог. Декодеры проверены по исходным декларациям,
включая null, ограничения групп, форму агрегатов и скрытые поля конкурсных строк.

## Сверка кода и зависимостей

TypeScript-парсер проверил локальные импорты и реэкспорты 87 модулей.
Все пути разрешаются, циклов нет. Из исходного `main` сопоставлены 54
декларации, в том числе переключатели маршрутов и декодеры всех перенесённых
DTO. В шести экранах с вынесенными ресурсами или типами совпал JSX return.
Код двух перенесённых контроллеров подписок и поиска, включая эффекты и сетевые
операции, совпадает с предыдущими телами страниц. Синхронизация фильтров
сохранила реализацию и получила новое имя.
[Полная карта локальных зависимостей](evidence/frontend-architecture-dependencies.json).

Проверка исходного UI отдельно сравнила 17 деклараций demo-страниц и
ProgramCard, а также оставшуюся общую разметку UI. Она отклонила контрольные
подмены числа в ForecastResult и подписи в ProgramCard. Для сверки использован
Git SHA исходного main. Исторический checkout React v3 локально недоступен.

Три CSS, навигационные примитивы, вход, транспорт, механика гостевых ресурсов,
хранилище аккаунта и тесты фронтенда совпадают с базой по Git. Сборочные
зависимости и конфигурация развёртывания остаются на прежних путях.

## Визуальное сравнение

Команда из `frontend/` — `node scripts/compare-main.mjs 5ca1cca --layout-matrix`.
Playwright Chromium сравнил 29 маршрутов из исходного инвентаря и шесть
дополнительных для конкурсов, покрытия и email-действий. Все 490 пар
побайтно совпали, по 70 на каждой из ширин 320, 375, 390, 768, 1024, 1440
и 1920 px. Текст, итоговые URL, запросы, HTTP-статусы и размеры переполнения
совпали. Неожиданных ошибок браузера нет. Снимки одной пары получают один
read-only ответ из изолированного FastAPI, а интерактивные тесты обращаются
к API напрямую.

| Ширина | Маршрут | Режим | Переполнение до и после |
| --- | --- | --- | ---: |
| 320 px | `/how-it-works` | default | 2 px |
| 320 px | `/how-it-works` | demo | 2 px |
| 320 px | `/app/watchlist/add` | default | 33 px |
| 320 px | `/app/forecast/method` | demo | 61 px |
| 375 px | `/app/forecast/method` | demo | 6 px |

В остальных 485 парах переполнения нет. Указанные пять случаев присутствуют
на исходном main. Их исправление меняет адаптивную раскладку и выходит за
рамки рефакторинга. Полный список маршрутов, SHA исходного отчёта и хеши
примеров пар PNG доступны в [сводке](evidence/frontend-architecture-visual.json).

Обычный suite проверял живой локальный FastAPI, маршруты, гостевые подписки,
каталог и пагинацию. Существующие тесты авторизации, keyboard focus,
loading/error/empty/success, отмены и смены сессии выполнены в том же наборе.
Первый запуск завершился с 386 успешными тестами и одним сетевым сбоем.
Трасса показала `net::ERR_NO_BUFFER_SPACE` до ответа HTTP на запрос карточки
программы. Полный повтор прошёл 387 тестов, отдельный повтор пути каталога
дал 10/10. Код и ожидания тестов между этими запусками совпадают.

SHA256 собранного CSS в исходной и итоговой версиях совпал:
`57dc182aac46b286f5b405215be49e6ea613c3c95aeea663cabbcab7d7a0c94c`.
Отдельный локальный запуск Docker/PostgreSQL недоступен в этом окружении.
Обычная проверка Chrome использует временную базу, проверки реального
PostgreSQL для авторизации остаются в существующем GitHub Actions workflow.
