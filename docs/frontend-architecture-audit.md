## Порядок работы и проверки

1. Привязать исходную сборку к полному SHA текущего main и сохранить результаты
   полного `npm test` до изменений. Сравнение снимков каждый раз поднимает
   Git-архив той же базы на отдельных локальных портах.
2. Первый PR переносит демонстрационные страницы и расширяет существующий
   инструмент визуальной сверки. До публикации выполнить обычный frontend
   suite и матрицу на семи ширинах для 35 маршрутов в двух режимах.
3. Связанный PR переносит live/auth/public области, выделяет app-композицию,
   устраняет обратную зависимость конкурсов от каталога и разносит декодеры.
   Маршруты, тексты, обработчики, ключи, порядок эффектов и DTO сохраняются.
4. Проверить итоговый граф, намеренно оставленные границы, отсутствие изменений
   CSS, полные тесты и реальный API. Повторить матрицу относительно исходного
   main, чтобы сравнение доказывало свойства всей серии PR.
5. Опубликовать обе части без merge. Во втором PR указать базу первого,
   независимый SHA сравнения, итоговую структуру и оставшиеся ограничения.

Сохранённые эталоны, тесты и переходы demo/real менять нельзя. Исторический
checkout `admitflow-frontend-v3-main` локально отсутствует. Визуальная база
для серии — воспроизводимая Git-ревизия. Полный suite упражняет API и действия
пользователей отдельно от визуального сравнения на общих ответах FastAPI.

## Результат первой части

`AppPages.tsx` сократился с 323 до 10 строк. Все 15 имён страниц и тип
сохранены. Перенесены обзор, прогноз, избранное, демонстрационные конкурсы,
сравнение, профиль/настройки, справочные экраны и системные состояния. Обзор
и результат прогноза используют общий заголовок. Страницы остались на исходных
маршрутах и используют React, demo-факты и прежние UI/RouteLink.

На новой базе прошли `npm run typecheck`, `npm run lint`, `npm run build`
и `npm test` (387 тестов). В полном повторе `node scripts/compare-main.mjs
5ca1cca --layout-matrix` все 490 пар совпали побайтно. Сохранены URL, текст,
API-запросы и ответы. Пять случаев переполнения на 320/375 px равны main.

Первый параллельный захват отметил 70 отличающихся пикселей в одном снимке
`/app/watchlist/add` при 768 px (наибольшее различие канала RGB — 2).
Текст, URL, API и размеры в этой паре совпали. Для повтора захват PNG
выполнялся последовательно, пороги и эталоны сохранены. Хеш исходного
отчёта повтора и примеры снимков сохранены в
[сводке первой части](evidence/frontend-architecture-demo-visual.json).
