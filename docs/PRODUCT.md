# Продукт и границы MVP

Версия плана: 1.0. Дата составления: 2026-10-31. Требования и границы MVP зафиксированы ниже.

## 1. Какую проблему решаем

Абитуриент видит порядковый номер в списке, но не понимает своего положения в конкретном конкурсе. Он вручную открывает несколько сайтов, пересчитывает людей, отслеживает согласия и изменения. Ошибка в трактовке списка может повлиять на выбор направления.

«Абитуриент» объединяет выбранные направления, показывает источник и время данных, объясняет текущую оценку и условия, при которых она изменится. Основной результат: человек понимает, что известно сейчас, какие допущения сделаны и где проверить исходный список.

## 2. Подтверждённые требования

- Сайт и продукт называются «Абитуриент».
- Дизайн основан на четырёх PNG: desktop/mobile, light/dark. Шрифты Inter и JetBrains Mono.
- Интерфейс на React; качество и поддерживаемость важнее формального совпадения названий технологий.
- Срок целевого MVP — месяц.
- Продуктовые приоритеты и приёмка определяют порядок реализации roadmap.
- Цель покрытия — все вузы России.
- Пользователь хочет понимать возможность поступления, включая ситуацию, когда исходный номер ниже границы бюджетных мест.
- Нужен подробный сохраняемый roadmap, позволяющий продолжать работу после многих шагов и перезапусков.

## 3. Что означает «все вузы»

Три разных измерения публикуются отдельно:

1. **Каталог:** какие организации, филиалы и страницы приёма известны сервису. Полнота считается относительно конкретного датированного реестра, с оговорёнными уровнями обучения и филиалами.
2. **Ручная работа:** возможность добавить ссылку и цифры для любого вуза, если пользователь понимает выбранную конкурсную группу. Это не признак подключения сайта.
3. **Автоматизация:** какие источники, сезоны и конкурсные группы действительно импортируются и проверяются. Один адаптер иногда подходит нескольким вузам; это нужно доказать тестами на каждом источнике.

Архитектура изначально допускает национальный масштаб. Обещание автоматического охвата всех вузов за месяц не подтверждено аудитом источников и не включается в рекламу. Первый обязательный рубеж автоматизации — два независимых официальных источника с проверенным результатом; после него подключаются остальные по трудозатратам и полезности. Это план выпуска, а не согласованное с пользователем сокращение долгосрочной цели.

## 4. Пользовательские сценарии

### U1. Быстро проверить положение

Вход с лендинга → выбор поддерживаемой конкурсной группы → ввод публичного идентификатора, применяемого именно этим источником → просмотр найденной строки → подтверждение совпадения → расчёт. Если данных недостаточно, интерфейс перечисляет недостающие поля, предлагает источник и ручной сценарий.

### U2. Сравнить направления

Сохранить несколько направлений → открыть единый список → увидеть положение, сценарий согласий, число доступных мест, изменение и время последнего успешного обновления. Сортировка по изменению, вузу или времени. Никакое направление не получает пометку «гарантированно поступите».

В ручном промежуточном этапе B05 доступны поиск по названию/вузу, фильтр сценария, сортировка по вузу/дате сохранения/дате добавления и печатный отчёт отфильтрованного списка с источником, датой и допущениями. История показывает все введённые числа, точные даты и позволяет выбрать любую пару загруженных ручных снимков. Ручное обновление кабинета перечитывает свои сохранения, не загружает данные вузов. Сортировка по автоматически обнаруженному изменению остаётся частью будущего автоматического пути.

### U3. Понять изменение

Открыть историю → сравнить две версии → увидеть, что изменилось: число конкурентов, согласие, количество мест, собственный статус или правило расчёта. Сохранять версию алгоритма; пересчёт старого снимка новым алгоритмом явно отделять от исходного результата.

### U4. Источник перестал отвечать

Последние корректные данные остаются видны с датой. Появляется пометка устаревания/ошибки. Прогноз, требующий свежих сведений, недоступен. После восстановления результат пересчитывается из нового проверенного снимка.

### U5. Вуз пока не подключён

Показать точный статус подключения; предложить ручной ввод или поддерживаемый импорт файла. Заявка на подключение сохраняет URL и название без обещания срока. Произвольная пользовательская ссылка не запускает неограниченный серверный запрос.

### U6. Удалить свои данные

Удаление выбранного направления с подтверждением; возможность очистить все собственные сохранения. История другого пользователя недоступна по подбору ID. Политика хранения и срок гостевой сессии объяснены до сохранения.

## 5. Обязательный результат первого месяца

| Область | Минимум для полноценного автоматизированного MVP |
| --- | --- |
| Интерфейс | Лендинг, калькулятор, каталог/поиск, направления, детали/история, состояния ошибок; 2 темы |
| Сохранение | Рабочая гостевая сессия и сохранение на сервере; понятный срок доступа; изоляция пользователей |
| Данные | Два проверенных официальных источника; автоматические задачи обновления; история снимков |
| Расчёт | Версионированная модель для явно поддержанных конкурсных групп; объяснения; отказ при неполных данных |
| Сравнение | Карточки направлений и изменение после обновления; источник и актуальность каждой оценки |
| Оповещение | Изменения и ошибки видны внутри приложения; внешние рассылки не являются условием MVP |
| Эксплуатация | HTTPS, PostgreSQL, миграции, резервная копия и проверенное восстановление, наблюдаемость |
| Проверка | Автоматические тесты расчётов/API/пользовательского пути; сверка реальных списков; отсутствие критических дефектов |

Рабочий ручной трекер — промежуточный результат. Если импорт не прошёл проверку, выпуск можно честно назвать ручной beta; это не выполнение цели автоматизированного MVP.

## 6. Роль ИИ

В MVP числовой результат считает воспроизводимый алгоритм. Объяснение сначала формируется шаблонами из структурированных фактов. Сценарий «если согласия изменятся» полезен даже без статистического прогноза.

ИИ может позднее объяснять результаты разговорным языком и помогать разбирать неизвестные форматы под контролем валидации. Числовая вероятность поступления — отдельная модель, требующая исторических временных снимков и проверки на будущих относительно обучения данных. Никакой случайной оценки «шанс 87%» по одному списку.

## 7. Отложенные функции

Внешние email/Telegram/push-уведомления, полноценные аккаунты с несколькими устройствами, платные тарифы, мобильное приложение, универсальная поддержка PDF/OCR, сложные способы приёма и прогноз вероятности вводятся после прохождения основных контрольных точек. Полноценные аккаунты можно поднять в приоритете, если гостевой доступ не подходит для приёмки; это отдельное решение с пересчётом плана.

## 8. Метрики успеха

- Первый успешный расчёт для поддержанной группы без помощи разработчика: целевой медианный путь до 3 минут в пяти пробных заданиях.
- Пользователь может назвать источник и время данных и объяснить отличие сценария от гарантии: минимум 4 из 5 пробных заданий; без доступных участников результат остаётся непроверенным.
- Все контрольные примеры расчёта дают ожидаемый результат; любое существенное расхождение блокирует релиз.
- В интерфейсе нет автоматической оценки без provenance, качества данных и версии модели.
- Есть измеряемый отчёт о покрытии: каталог / источники с адаптером / успешно обновляемые группы. Количество записей каталога не используется как число интеграций.

Эти числа — целевые критерии проекта, а не уже измеренные результаты.
