# Продукт AdmitFlow

AdmitFlow помогает выбирать университет и направление, понимать конкурсную
ситуацию и в перспективе оценивать поступление на проверенных данных.
Визуальный эталон — frontend v3. Сохранение старого ручного калькулятора
не определяет новый продукт.

Сейчас работает публичный каталог: университет → его кампании/программы →
конкретный конкурс. Подтверждённые факты имеют ID, год, источник и дату
проверки. Справочник MICCEDU — датированный перечень участников мониторинга,
не полный актуальный реестр лицензий. Первые программы — два архивных
конкурса СГУ 2026, без подмены данными кампании 2027.

Неизвестные бюджетные места/проходные/требования должны оставаться null и
«Нет данных». Прогнозные проценты прототипа явно демонстрационные. Нет
обученной модели, калибровки и оснований выдавать их за реальный прогноз.
Аккаунты, сохранение реальных catalog IDs, сравнение, live lists, аналитика,
уведомления и ML пока не завершены как новые продуктовые функции.

Текущий этап — очистка и проверка инфраструктуры, **без новых функций**.
Сохраняются полезные парсеры, нормализация, история, jobs и модели БД.
Не удаляются существующие PostgreSQL данные, volumes и applied migrations.
Непроверенный Docker/PostgreSQL контур — блокер, а не успешная приёмка.

Дальнейшая работа выбирается отдельно после завершения очистки и native
проверки. ML требует качественной истории кампаний/outcomes, временного
разделения данных и заранее выбранных метрик. Ни процент выполнения старого
MVP, ни done исторических задач не означает готовность нового сервиса.
