# Постоянный контекст AdmitFlow

Начните с [README](README.md) и документа по затронутой части проекта. React v3 находится в `frontend/`, все npm-команды запускаются из него. FastAPI, SQLAlchemy, миграции и импорт находятся в `backend/`. Визуальный эталон — исходный React/CSS v3. Сохраняйте совместимость существующих данных PostgreSQL и применённых миграций.

## Документация

- Для обычной задачи достаточно кратко описать результат и проверки в ответе или в существующем PR. Для личной задачи достаточно запроса в чате. Jira и реестр используйте для работы, которая уже там ведётся.
- Меняйте существующее руководство, только если изменились архитектура, контракт, запуск, эксплуатация или правила данных. Добавляйте новый файл в `docs/` только по явному запросу или если он нужен коду, тестам, CI либо для обязательной воспроизводимости и ему нет места в существующем документе.
- Отчёты по PR, планы, журналы сессий, снимки статуса, скриншоты, JSON замеров и EXPLAIN храните в задаче, артефактах CI или локальном `test-results/`. Для ревью достаточно команды, SHA, окружения, ключевого результата и ссылки на доказательство.

## Работа с проектом

- Для зарегистрированной задачи используйте `python scripts/roadmap.py --task Tnnn`. При фактическом изменении её статуса обновите `TASKS.json` и при необходимости `STATE.json`, затем выполните `python scripts/roadmap.py --render --check`. `CHECKLIST.md` генерируется автоматически.
- Используйте [критерии проверки](docs/DEVELOPMENT.md#критерии-проверки) и `python scripts/check_doc_links.py` при изменении документации.
- Меняйте версию правил расчёта, кампании, состава конкурса или согласий вместе с [контрактом данных](docs/DATA_RULES.md) и тестами. Различайте ручной режим, архив, свежий список и неподдержанный источник.
- Используйте небольшие коммиты с английскими Conventional Commits и настроенное авторство Git. Сохраняйте опубликованную историю.
