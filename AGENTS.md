# Постоянный контекст AdmitFlow

Начните с [README](README.md) и документа по затронутой части проекта. React v3 находится в `frontend/`, все npm-команды запускаются из него. FastAPI, SQLAlchemy, миграции и импорт находятся в `backend/`. Визуальный эталон — исходный React/CSS v3. Сохраняйте совместимость существующих данных PostgreSQL и применённых миграций.

- Если продолжаете задачу из реестра, используйте `python scripts/roadmap.py --context` или `--task Tnnn` из корня. `--next` показывает доступные задачи, `--log` читает историю из закреплённого Git-коммита.
- `docs/TASKS.json` хранит статусы, зависимости, критерии и доказательства. `docs/STATE.json` хранит указатель продолжения. При изменении статуса обновите реестр и указатель, затем выполните `python scripts/roadmap.py --render --check`. `CHECKLIST.md` генерируется автоматически. Держите одну задачу в `in_progress` и отмечайте `done` только после проверки критериев.
- Результаты текущей работы фиксируйте в задаче или PR. Для воспроизводимости указывайте SHA, команду и окружение. Используйте [критерии проверки](docs/DEVELOPMENT.md#критерии-проверки) и `python scripts/check_doc_links.py` при изменении документации.
- Меняйте версию правил расчёта, кампании, состава конкурса или согласий вместе с [контрактом данных](docs/DATA_RULES.md) и тестами. Различайте ручной режим, архив, свежий список и неподдержанный источник.
- Для работы по плану пользователь предпочитает подходы по пять задач. После каждой завершённой задачи сделайте коммит и проверку. По итогам подхода дайте краткую сводку.
- Используйте небольшие коммиты с английскими Conventional Commits и настроенное авторство Git. Сохраняйте опубликованную историю.
