# AdmitFlow

AdmitFlow помогает абитуриентам искать вузы и программы, читать требования к поступлению и отслеживать свою позицию в доступных конкурсных списках. Интерфейс написан на React и TypeScript, API — на FastAPI, данные хранятся в PostgreSQL.

## Что доступно

- **Вузы** (`/universities`). Поиск по названию и региону, карточки вузов и филиалов. Справочник основан на мониторинге MICCEDU 2025 и выгрузке реестра аккредитации от 10 ноября 2026 года. [Источники и покрытие](docs/catalog-coverage.md)
- **Программы** (`/programs`). В штатную поставку входят две записи по проверенным архивным конкурсам СГУ за 2026 год. В карточках указаны источник и подтверждённые требования ЕГЭ, когда они известны. [Контракт каталога](docs/API.md#публичный-каталог-v3)
- **Конкурсы и отслеживание** (`/app/competitions`, `/app/watchlist`). Для конкурса с загруженным списком можно посмотреть его сводку, найти и подтвердить свою запись, добавить её в гостевые подписки и просматривать события. Локальный старт загружает сведения о вузах и программах. Загрузка самих списков выполняется отдельно. [Запуск и импорт](docs/catalog-runbook.md)
- **Покрытие** (`/app/coverage`). Отдельные показатели по вузам в справочнике, программам, требованиям ЕГЭ и импортированным спискам. База сравнения — 785 головных вузов из выгрузки реестра. [Как считаются показатели](docs/evidence/kan-221-coverage-dashboard.md)

## Состояние проекта на 21 ноября 2026 года

- **Кампания 2027.** Публичный API и интерфейс показывают проверенные программы после явной публикации. Штатный локальный запуск добавляет архив СГУ. В отдельной PostgreSQL репетиции подтверждены две программы ВШЭ за 2027 год, то есть 1 из 785 головных вузов. PR #31 добавил возобновляемый пакетный запуск. Национальный охват остаётся открытой задачей. [Контракт](docs/sources/program-catalog/contract.md) · [Пакетный импорт](docs/KAN-218-PR3.md)
- **Регистрация и восстановление доступа** реализованы за флагом `AUTH_ENABLED`, который по умолчанию выключен. Доставка писем через реальный SMTP и выпуск в HTTPS-окружение ещё требуют подтверждения. [Готовность к выпуску](docs/RELEASE_GATES.md)
- **Прогноз** можно посмотреть в деморежиме на `/app/forecast?mode=demo`. Интеграция ML остаётся в планах. В `ml/` описана подготовка исторических данных. [Описание данных](ml/README.md)

## Локальный запуск

Нужны Python 3.10+, запущенный Docker Engine с Linux-контейнерами и Docker Compose v2 с поддержкой `--wait`. Для первого запуска нужен доступ к реестрам образов и пакетов. Выполните команду из корня репозитория.

```bash
python scripts/local_smoke.py
```

После `PASS` откройте [http://localhost:8080](http://localhost:8080). Начать можно с `/universities` или `/programs`. API доступен по `/api` на том же адресе, готовность проверяется через `/api/ready`.

Скрипт делает резервную копию PostgreSQL перед миграциями, поднимает API и интерфейс, импортирует публичный каталог и проверяет, что данные сохраняются после пересоздания контейнеров. Стек остаётся запущенным. Отчёт и приватная резервная копия сохраняются в `test-results/local-start/`. С уже собранными образами можно повторить запуск с `--no-build`. [Отчёт о локальном запуске](docs/evidence/local-postgresql.md)

Если порт 8080 занят, скопируйте `.env.example` в `.env` и задайте `WEB_PORT`. На время проверки приостановите параллельные записи и импорт. Для остановки используйте `stop`. Тома `admitflow_postgres_data` и `admitflow_raw_data` сохраняются для следующего запуска.

```bash
docker compose stop
```

## Разработка и проверки

Для разработки без контейнеров используйте Node.js 24 и Python 3.12, как в CI. Vite запускается из `frontend/` командами `npm ci` и `npm run dev` и проксирует `/api` на `localhost:8000`. Для другого локального бэкенда задайте `API_PROXY_TARGET`. Изолированный FastAPI для работы над интерфейсом можно запустить с временной SQLite. [Инструкция для фронтенда](frontend/README.md) · [Запуск тестового API](docs/catalog-runbook.md#локальная-проверка-без-изменения-пользовательской-бд)

Команды проверки выполняются из `frontend/` после `npm ci`. Установите Python-зависимости в виртуальное окружение, которое будет использовать `npm test`.

```bash
python -m pip install -r ../backend/requirements-dev.txt -c ../backend/constraints.txt
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm test
```

При первой установке Chromium на Linux системные зависимости можно добавить командой `npx playwright install --with-deps chromium`, как в CI. В стандартном режиме Playwright поднимает FastAPI с временной SQLite. Для проверок миграций на отдельной PostgreSQL запустите `python scripts/test_postgres.py` из корня репозитория с установленными зависимостями бэкенда и запущенным Docker. [Проверки в CI](.github/workflows/ci.yml)

## Структура репозитория

| Папка | Содержимое |
| --- | --- |
| `frontend/` | Интерфейс React, API-клиент и тесты Playwright |
| `backend/` | FastAPI, SQLAlchemy, миграции Alembic, каталог и обработка источников |
| `scripts/` | Локальный запуск, проверка PostgreSQL и утилиты для работы с данными |
| `shared/` | Тестовые данные исторического ручного режима |
| `ml/` | Документация по подготовке исторических данных |
| `docs/` | Архитектура, контракты, отчёты о проверках и план работ |
